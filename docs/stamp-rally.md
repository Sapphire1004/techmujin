# スタンプラリーの試作

完成前の機能を共有し、方向性や操作感のフィードバックを受けるための試作です。未完了の仕様は下記の確認項目で明示しています。

## 現在の仕様

- モバイルファーストのWebアプリとして、会場のQRコードを読み取ってスタンプを集めます。PCでは共通ヘッダー、モバイルではハンバーガーメニューから4画面を切り替えます。
- スマートフォンの標準カメラでQRを読み取り、表示されたURLを開くとスタンプを自動取得します。未参加の場合も、その場で参加とスタンプ取得が完了します。
- スマートフォンでの利用を推奨し、ブラウザー内の読み取りはカメラで行います。「参加する」を押すとカード作成とスキャン画面の表示を行い、そのままカメラへのアクセスを要求します。参加後も読み取りボタンからカメラを起動できます。同じサイトのQR URLと従来のテキストQRに対応します。
- チェックポイントは仮の5か所です。名称・説明は未確定で、会場案内のブースともまだ連携していません。
- 進行状況は利用中のブラウザーの `localStorage` に保存し、再読み込み時に復元します。
- 同じQRを再度読み取っても、取得数と最初の取得時刻は変わりません。
- 保存に成功すると、URLから `stamp` パラメーターを取り除きます。失敗した場合はURLを保持し、画面の「保存を再試行」から再試行できます。
- 同じブラウザーの別タブで取得した場合も、開いているスタンプカードに保存内容を反映します。
- 記録のリセット操作は画面に設けていません。
- ログイン、サーバー側の認証、不正取得の防止、景品の交換管理は実装していません。参加者の良識に基づく運用を想定しています。

## ローカルでの確認

依存関係をインストールし、開発サーバーを起動します。

```bash
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1 --port 5176 --strictPort
```

`http://localhost:5176/?stamp=spot-1#stamp-rally` を開くと、チェックポイント1のスタンプが記録されます。`stamp` の値を変更すると他のチェックポイントも確認できます。`#timetable` でタイムテーブルへ戻れます。

既存プロジェクトの `node_modules` を共有しているローカル作業フォルダーでは、依存関係の自動再インストールを避けるため、次の起動コマンドを使用します。

```bash
pnpm --config.verify-deps-before-run=false run dev --host 127.0.0.1 --port 5176 --strictPort
```

カメラを使用するにはlocalhostまたはHTTPSの安全なコンテキストが必要です。スマートフォンで別の端末の開発サーバーを開く場合は、HTTPのLANアドレスではなくHTTPSのプレビュー環境などを使用してください。

## テスト用QR

画像の発行コマンド・印刷・配布方法は [QR作成・配布ガイド](./stamp-rally-qr.md) を参照してください。

QRコードには、デプロイ先のURLとチェックポイントIDを入れます。下記のURLはローカル確認用です。会場に置くQRは、配布先を決めてから同じホストのHTTPS URLに置き換えて作成してください。

```text
http://localhost:5176/?stamp=spot-1#stamp-rally
http://localhost:5176/?stamp=spot-2#stamp-rally
http://localhost:5176/?stamp=spot-3#stamp-rally
http://localhost:5176/?stamp=spot-4#stamp-rally
http://localhost:5176/?stamp=spot-5#stamp-rally
```

`#stamp-rally` がなくても取得でき、スタンプラリー画面へ移動します。存在しないID、空のID、複数の `stamp` パラメーターは無効です。無効なURLを開いても参加や取得は行いません。

NFCタグでも同じURLを開けば同じ処理が動きます。Web NFCによるタグの読み書きは実装していません。

保存キーと形式は既存の `techmujin:stamp-rally:v1` を維持しています。同じサイト・同じブラウザーでは記録を引き継げますが、別のブラウザーや端末とは同期されません。標準カメラが開くブラウザーと普段使用するブラウザーが異なる場合も記録は分かれます。サイトデータを削除すると記録も失われます。

## 検証コマンド

```bash
pnpm test:stamp-rally
pnpm test:stamp-rally-ui
pnpm test:stamp-qr
pnpm test:navigation
pnpm typecheck
pnpm build
```

単体テストではNode.js 22.18以降を使用してください。アプリのNode.js要件は `package.json` を参照してください。

## フィードバック・追加確認が必要な項目

- 「ブース訪問・収集・完成」を伝える案内文と参加フロー
- 正式なチェックポイント数・名称・説明
- スマートフォンでのレイアウト、タップ領域、片手操作
- iOS / Android実機での標準カメラ → URLを開く → 自動取得、再訪時の記録復元
- ブラウザー内スキャナーのカメラ許可、QR読み取り
- 統合した共通ヘッダー・ナビゲーションの実機での操作確認

自動検証では、カードの単体テストに加え、Happy DOM上で実際のReact画面を描画し、自動参加・重複・記録復元・保存失敗後の再試行・別タブの保存通知・画面遷移を確認します。Happy DOMはテスト専用で、本番アプリには含めません。

実機では、別画面や印刷したQRを標準カメラで読み取り、リンクを開いてスタンプが増えること、同じQRでは増えないこと、再読み込み後も記録が残ることを確認してください。実機でのカメラ読み取りを検証済みとはしていません。
